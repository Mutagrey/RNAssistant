# Решения по UI RNAssistant

## 2026-11-12 — Developer configuration: scope Approved, UI In Review

Пользователь уточнил Developer внутри Settings: пароль открывает скрытые настройки;
private key по пути нужен при подписи. Один deployment-config.bin для всех, base64
допустим как сокрытие от случайного просмотра; основная защита — RSA signature.
Manual Browser default deny; подписанный checkbox разрешает любые HTTP(S)-сайты
только пользователю. Policy version в приложении должна точно совпадать с подписанной;
это отдельная версия политики, не автоматическая привязка к каждому product patch.
Ключи — обычный encrypted .bin, без сертификатов, PFX/CRT и certificate store.
Разовые C# utilities для Mac и по запросу Windows GUI используют общий код;
public trust включается в сборку, private key не попадает в Git/поставку приложения.
[Настройка и ограничения](../browser/03_CONTRACTS.md#signed-access).


Owner: Web presentation; утверждает пользователь.
Общий журнал UI-решений: Demo P0–P3 и переход к модернизации production.
Нормативные границы — в [UI Architecture](UI_ARCHITECTURE.md); здесь история согласований.

Статусы: `Proposed`, `In Review`, `Approved`, `Superseded`, `Open Decision`.
`Approved` требует явного согласия; молчание и удачный browser-check им не являются.
`Completed` обозначает только технический checkpoint, не согласование дизайна.

### Zoom out: навигация и просмотры — 2026-11-02

Approved requirement: пользователь требует единую систему для Материалов,
Библиотеки, будущих Файлов и прочих источников; HTML/plugin — общий Browser,
форматные viewers — самостоятельные вкладки. Прямое уточнение «не спеши слепо
делать, сделай zoom out» приостанавливает частный перенос plugin preview до
проектирования общей схемы. Реализации placement S3b ещё нет.

Proposed design: общая navigation presentation с предметными adapters → один
open route существующего DockWorkspace → view instance с exact target → текущий
ViewerRegistry, включая общий Browser. Границы/owners, UX и S3b.1–S3b.3 записаны
в четырёх canonical UI-docs. Это проект для ревью, не объявление реализованной
унификации или подтверждение всех деталей пользователем. Второй store/kernel,
новая Shell, tree framework и plugin-only browser не вводятся.

Дополнительное явное требование: идти от общего к частному — сначала общие типы
и возможности, затем частные экраны; подключение через архитектурные контракты
вместо специальных условий в Shell. Поэтому S3b.0 фиксирует модель и матрицу
до реализации S3b.1–S3b.3. Конкретный дизайн контрактов остаётся Proposed;
направление и необходимость этой проработки подтверждены пользователем.

«Коммит и давай сделаем» разрешает сохранить этот план и начать S3b.1 от общих
контрактов к двум реальным consumers. Визуальное ревью и behavioral gates каждого
среза сохраняются; это не автоматическое закрытие S3b.2/S3b.3 или Windows evidence.

Уточнение пользователя про VBA и другие панели включено в явную таблицу S3b/S4:
общие types/capabilities и NavigationPane применяются к ним тоже, но domain reads
и команды остаются у источника. S3b.1 реализует первые два consumers и проходит
ревью; это не утверждение о переносе всех навигационных панелей.
