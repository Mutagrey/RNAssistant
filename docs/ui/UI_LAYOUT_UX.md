## Цель P3 после уточнения пользователя

**Approved — направление:** сохранить привычный production UI внутри согласованной
оболочки Dockview и точечно улучшить неудобства. Основа — действующие экраны `web/`,
доступные для сравнения через существующий
[product preview](http://127.0.0.1:8897/product-preview.html). Это только образец;
production-файлы не копируются и не изменяются. По подсказке пользователя готовый
mock-чат переиспользован в iframe внутри Dockview через небольшой Demo-адаптер.
Первый самостоятельный дизайн чата/инспектора P3 отклонён как направление;
его отдельный renderer, имитация выполнения и снимки удалены.

Главный результат — согласованные внешний вид, действия, состояния и критерии
проверки, чтобы при будущем внедрении не проектировать UX заново. Код Demo нужен
только для проверки взаимодействия: вкладки, resize, меню, ввод, раскрытия и
переключаемые примеры состояний. Не воспроизводить runtime, очередь запросов,
streaming, хранение чатов или исполнение инструментов; не развивать таймерную
имитацию чата в отдельный движок. Повторное использование кода Demo не является
самоцелью; будущая реализация опирается на существующие production-компоненты.

Для каждого изменения фиксировать проблему, ожидаемое поведение, минимальный
пример и проверку. Утверждение визуального решения и подтверждение исправления
production-багов — разные статусы.

| Проблема или вопрос | Ожидаемое поведение / минимальный пример | Проверка и статус |
|---|---|---|
| P3 визуально ушёл от привычного чата — замечание пользователя | Взять форму сообщений, компактные материалы и composer из production как образец; показать один заполненный чат в Dockview | Сравнить знакомые элементы и отдельно назвать каждое улучшение; направление Approved, конкретный вид In Review |
| Управление областями мешает внутри содержимого — замечание пользователя | Верхние кнопки областей; «+» выбирает экран, две иконки создают область справа/снизу, «Закрыть группу» действует на одну группу | Уже реализовано в Demo; смысл команд Approved, детали размеров In Review |
| Черновик, фокус и прокрутка при смене/перемещении вкладки — сценарий проверки, не подтверждённый production-баг | Ввести текст, открыть другую вкладку, вернуться и переместить чат; контекст работы не сбрасывается | Сверить текст, позицию чтения и доступность ввода; Proposed |
| Длинный ответ и узкая панель — сценарий проверки, не подтверждённый production-баг | Поле ввода и основные действия остаются доступны; содержимое не выталкивает их за границы | Один длинный пример на широкой и узкой панели; Proposed |
| Выполнение, остановка и ошибка должны быть понятны | Несколько переключаемых визуальных состояний с доступным следующим действием; без имитации настоящего выполнения | Различимы текущий процесс, остановка и ошибка, незавершённое не выглядит успехом; Proposed |
| Связь инспектора с чатом — открытый вопрос | Использовать знакомые production-разделы; определить, какой чат инспектор показывает после смены вкладки | Два чата и один инспектор; поведение и состав требуют отдельного ревью, Open Decision |

Ближайшее ревью ограничено одним чатом и composer на production-основе:
сравнить сообщения и плотность; набрать текст и открыть меню действий;
сузить панель и проверить доступность ввода. Сначала обозначить конкретные
отличия и согласовать их, затем детализировать инспектор и остальные экраны.

## Текущая реализация P3 — In Review

`chat-views.js` использует существующий `/preview/web/` с `mock-bridge.js`:
сообщения, Markdown, материалы, composer, меню действий и выбор модели принадлежат
неизменённому production UI. Заполненный и пустой чаты — существующие fixtures.
Новых реализаций отправки, ответа, остановки или хранения беседы нет.
Их поведение в preview остаётся симуляцией существующего mock, а не Office.

Изменения относительно production видны отдельно:

- Внутренние rail, дерево, заголовок чата и кнопка инспектора скрыты: эти роли
  выполняет Dockview-оболочка. Дублирующие панели не занимают место в чате.
- Материал примера открывается вкладкой Dockview; меню действий закрывается при
  переходе. Тема и акцент следуют настройкам оболочки.
- При ширине панели ниже 400 px уменьшены внешние отступы composer. Прокрутка
  остаётся внутри ленты, поле ввода сохраняет production-поведение роста.
- Загрузка iframe прикрыта коротким статусом, чтобы не мелькала вторая оболочка.
  В Demo корневой `overflow: clip` устраняет наблюдавшееся смещение всей оболочки
  при фокусировке встроенного чата; это найденный дефект композиции Demo.

Инспектор остаётся статическим макетом P1 и пока не следует за активным чатом.
Полноценная связь инспектора, ветвление/удаление чатов и обмен их состоянием
между окнами не входят в этот адаптер. Каждая вкладка чата загружает отдельный
экземпляр существующего UI; это способ визуального сравнения, не предлагаемая
production-архитектура или проверка производительности. Переключение вкладок
сохраняет iframe; его пересоздание при закрытии/повторном открытии или замене
раскладки заново загружает mock-переписку. Желаемое сохранение беседы при docking
остаётся требованием; этот временный способ показа его не доказывает.
Черновики использует существующий preview-store в sessionStorage, с разными
ключами для двух примеров, чтобы их записи не перетирались.
Owner и условие удаления адаптера — в [Migration Map](../stabilization/MIGRATION_MAP.md).

Проверено во встроенном браузере: заполненный/пустой чат, меню действий, открытие
материала в Dockview, два независимых черновика и возврат закрытого чата; обе темы,
ширина оболочки 360 px, рост ввода до шести строк со внутренней прокруткой.
На 360 px composer не переполняется, фокус не сдвигает верхнюю панель.
[Текущий вид](review/p3-production-chat.png), [узкая панель](review/p3-production-chat-narrow.png).
Открытое наблюдение: в журнале сессии были две ошибки `MutationObserver.observe`;
источник не локализован, повтор загрузки, смены ширины и быстрого закрытия чата
их не воспроизвёл. Это не объявлено исправленным production-дефектом.
Визуальное утверждение этого варианта ещё не получено.

## P0: исходный Demo

Исходный `prototypes/ui/index.html` имел rail, дерево, чат, материалы, библиотеку,
VBA, настройки и две темы. `app.js` заменял одну область при смене route;
`split-layout.js` самостоятельно управлял ширинами. Инспектор был подэкраном чата,
общего пространства вкладок не было. Полосы ревью и крупные заголовки занимали
много места; у Markdown встречался повторный переключатель просмотра/исходника.

В P1 старые Demo-only route/render/split-модули удалены, вход переключён на один
Dockview. Сохранены fixtures, assets, локальные иконки и Markdown vendors.
`product-preview.html`, его mock bridge и `demo/RNAssistant.MockDemo/` остаются
отдельными прежними demo; production consumers и исходники `web/` не изменены.
Историческое описание прежнего UI — [ui-design.md](../ui-design.md).

## Оболочка

- **Согласовано пользователем:** кнопки сворачивания/разворачивания — в верхней
  панели. Внутри панелей их нет. Сверху доступны навигация, инструменты,
  разворачивание активной группы / восстановление, меню панелей/компоновки/демо и тема.
  Название и логотип приложения убраны по прямому пожеланию пользователя.
  Вместо них примеряется имя документа; настройки перенесены в правый верхний угол.
  Эти два варианта пока In Review. Имя берётся из общей fixture, это не live Office target.
- Слева rail меняет контекст дерева, не закрывая вкладки. Навигация сворачивается;
  отдельный separator меняет только ширину дерева, включая управление клавишами.
- Центр и инструменты — один Dockview. Панель можно перетащить в другую группу,
  открыть новую область справа/снизу, закрыть и открыть снова. Вкладки и split принадлежат
  Dockview, собственного docking engine нет.
- В заголовке группы — «+», две прямые кнопки новой области справа/снизу
  с оригинальными иконками VS Code и «⋯». Исходный экран остаётся на месте;
  в новой области открывается вкладка «Выберите экран» с поиском и каталогом.
  Выбор заменяет эту вкладку. Уже открытый экран переносится сюда без копии.
  Это работает и при единственной вкладке в исходной группе.
- Поиск получает фокус; Enter открывает первый результат. Пустую вкладку можно
  закрыть обычным крестиком. Состав незаполненных областей сохраняется в раскладке,
  строка поиска — только до закрытия/перезагрузки страницы.
- Новые области создаются только при достаточном месте: текущая группа должна
  вмещать обе части. Проверка и подсказки — в `splitUnavailable` (`app.js`).
  При малой ширине/высоте соответствующая кнопка выключена; в узком режиме
  обе кнопки выключены. Это устраняет переполнение от повторных нажатий.
- «⋯» содержит объединение, закрытие текущей вкладки и «Закрыть группу»
  вместе со всеми её вкладками. Другие группы сохраняются. Заголовка «Активная вкладка»
  и старых четырёх направлений нет. Ручная сохранённая раскладка остаётся.
  Возврат — «Панели» / «Компоновка»; ограничения состояния mock-чата указаны выше.
  Разворачивание активной группы остаётся сверху; Escape возвращает обычный вид.
- **Согласовано 2026-11-02:** «+» открывает такую же вкладку выбора внутри текущей
  группы, включая узкий режим. Выбранный экран заменяет её; уже открытый
  переносится сюда без копии. Старое всплывающее меню «+» удалено.
  Каталог и renderer пунктов общие с верхним меню «Панели». Это открытие экрана;
  создание нового чата/документа будет отдельным действием при детализации сценариев.
- Кнопка инструментов скрывает/возвращает группы, содержащие только инструменты.
  Смешанная группа с чатом не скрывается; в таком случае кнопка открывает инспектор.
  Единственную рабочую группу скрыть нельзя. В узком режиме инспектор — вкладка.
- Меню «Панели» возвращает закрытые панели и фокусирует открытые по стабильному ID.
  Отдельные экземпляры одного примера не создаются.
- Низ содержит пометку Demo, количество вкладок/видимых групп и диагностику.

## Представления

| Представление | Как открыть | Текущая реализация |
|---|---|---|
| Анализ сентября / Сводка по регионам | Рабочая область, «Панели» или «Демо» | P3: production-чат на существующем mock; заполненный и пустой примеры |
| Инспектор | Верхняя кнопка, материалы или «Панели» | Mock-контекст с явной привязкой к «Анализу сентября» |
| Итоги сентября / Динамика продаж | Материалы, ресурсы чата, «Панели» | Markdown с одним переключателем исходника; пример графика |
| Браузер | Материалы или «Панели» | Статическая локальная страница без интернет-навигации |
| Файлы | Rail → Файлы | Все mock-источники открывают общий список; реальные файлы не читаются |
| Библиотека | Rail → Библиотека | Карточка одного навыка без запуска |
| Диагностика | Rail, статус или «Панели» | Фикстура журнала, не runtime events |
| Настройки | Правый верхний угол или «Панели» | В P2 добавлены выбор светлой/тёмной темы, палитра акцента и возврат к исходному виду; сохранение раскладки |

Файлы, материалы и библиотека — разные разделы навигации. Чат необязателен:
пресет «Материал и браузер» работает без него. Полные редакторы и состояния
loading/error/cancel относятся к P3.

## Раскладки и состояние

Пресеты в `app.js`: «Чат и инспектор», «Материал и браузер», «Одна группа вкладок».
Dockview сериализует состав, порядок и размеры групп. Автосохранение текущего вида
и ручное «Сохранить / Вернуть сохранённую» используют только browser localStorage
`rnassistant.prototype.dockview.p1`, version 1. Несовместимая раскладка явно
отклоняется с уведомлением; старые preferences прежнего Demo не импортируются.
Вкладки выбора имеют собственный компонент `chooser` и ID `choose-N`; они не
добавляются в каталог продуктовых экранов. Renderer принадлежит оболочке (`app.js`).
В P2 те же preferences содержат `accent` (исходный/палитра) и `theme` (светлая/тёмная).
Смена оформления не пересоздаёт представления и не меняет раскладку.

Режим материала и scroll принадлежат представлению в `panels.js`, а не его позиции.
Они остаются в памяти при закрытии/повторном открытии и замене раскладки, но не
после перезагрузки страницы. Чат P3 принадлежит существующему product preview:
черновики — его preview-store, пример переписки — память iframe. В layout и
localStorage оболочки содержимое чатов не записывается. Полное сохранение беседы
и смыслового якоря при пересоздании iframe не реализуется ради прототипа.

## Адаптация — In Review

- Широкое окно: дерево и независимые dock-группы. CSS-размеры оболочки — в
  `tokens.css`; стартовая ширина инструментов — в `app.js`.
- До 1000 px: дерево по умолчанию закрыто и открывается поверх workspace;
  выбор представления закрывает его. Пока дерево открыто, workspace inert.
- До 640 px: одна группа вкладок, drag/drop отключён. При возврате к широкому
  окну возвращается прежняя структура с учётом открытых/закрытых вкладок.
- Меню «Демо» задаёт ширину оболочки 900/560/360 px для визуального ревью.
  Это не эмуляция Office task pane.

## Dockview и границы

Используется MIT `dockview-core` **8.8.3**: локальный browser bundle со встроенным CSS.
[Источник, лицензия и хэши](../../prototypes/ui/vendor/dockview-8.8.3/README.md)
хранятся рядом; npm/bundler/CDN и новый loader не добавлены.
Тема использует публичные CSS variables Dockview.

Включён штатный `dndStrategy: 'pointer'`: HTML5 drag не дал переноса в проверенном
встроенном браузере, pointer drag сработал. Меню переноса даёт путь без drag.
Floating и popout отключены; отдельные окна не входят в P1.

## Запуск

Из корня репозитория:

```sh
python3 -B prototypes/serve_ui.py
```

Открыть [Demo P3](http://127.0.0.1:8897/index.html?review=p3).
Это существующий preview-server; assets локальные, внешняя сеть для запуска не
нужна. Для встроенного production-чата нужен этот HTTP-путь; при `file://`
вкладка показывает инструкцию запуска вместо неработающего iframe.

## Ревью P2 и следующий этап

P1 проверяет постоянный каркас будущего интерфейса: места действий, навигацию,
вкладки и пространство для содержимого. Тексты, карточки и набор полей mock-экранов
не утверждаются вместе с оболочкой. При P3 каркас снова проверяется на реалистичных
сценариях и состояниях; его можно скорректировать по результату. Технические
проверки выполняет агент; от пользователя требуется оценка удобства.

1. Открыть настройки справа сверху: выбрать акцент, затем вернуть «Исходный».
2. Выбрать светлую/тёмную тему: читаемы ли подписи, неактивные вкладки и границы.
3. Нажать «+», найти и выбрать экран; при необходимости повторить на ширине 360 px.

Пользователь выбрал оформление Dockview до A/B и настройку акцента. На ревью —
конкретный вид настроек; поведение «+» согласовано. Направление P3 уточнено выше:
один привычный production-чат, минимальные интерактивные примеры и конкретные
улучшения вместо самостоятельного дизайна чата и имитации его runtime.
Итоговый handoff пока не создаётся.
