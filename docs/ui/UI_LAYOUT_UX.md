# UI прототип: компоновка и навигация

Обновлено: 2026-11-02. Статус: **In Review**, оболочка P1 и настройки оформления P2.
Owner: Demo presentation (`prototypes/ui/`); визуальное утверждение — пользователь.
Область — независимый browser prototype по [заданию](../ui-prototype/00_START_HERE.md).
Поддерживать до отдельно разрешённой production-фазы; при замене переключить
ссылки и удалить устаревшую спецификацию. Согласования — в
[журнале решений](UI_DECISIONS.md), оформление — в [дизайн-системе](UI_DESIGN_SYSTEM.md).

## P0: исходный Demo

Исходный `prototypes/ui/index.html` имел rail, дерево, чат, материалы, библиотеку,
VBA, настройки и две темы. `app.js` заменял одну область при смене route;
`split-layout.js` самостоятельно управлял ширинами. Инспектор был подэкраном чата,
общего пространства вкладок не было. Полосы ревью и крупные заголовки занимали
много места; у Markdown встречался повторный переключатель просмотра/исходника.

В P1 старые Demo-only route/render/split-модули удалены, вход переключён на один
Dockview. Сохранены fixtures, assets, локальные иконки и Markdown vendors.
`product-preview.html`, его mock bridge и `demo/RNAssistant.MockDemo/` остаются
отдельными прежними demo; production consumers и исходники `web/` не изменены.
Историческое описание прежнего UI — [ui-design.md](../ui-design.md).

## Оболочка

- **Согласовано пользователем:** кнопки сворачивания/разворачивания — в верхней
  панели. Внутри панелей их нет. Сверху доступны навигация, инструменты,
  разворачивание активной группы / восстановление, меню панелей/компоновки/демо и тема.
  Название и логотип приложения убраны по прямому пожеланию пользователя.
  Вместо них примеряется имя документа; настройки перенесены в правый верхний угол.
  Эти два варианта пока In Review. Имя берётся из общей fixture, это не live Office target.
- Слева rail меняет контекст дерева, не закрывая вкладки. Навигация сворачивается;
  отдельный separator меняет только ширину дерева, включая управление клавишами.
- Центр и инструменты — один Dockview. Панель можно перетащить в другую группу,
  открыть новую область справа/снизу, закрыть и открыть снова. Вкладки и split принадлежат
  Dockview, собственного docking engine нет.
- В заголовке группы — «+», две прямые кнопки новой области справа/снизу
  с оригинальными иконками VS Code и «⋯». Исходный экран остаётся на месте;
  в новой области открывается вкладка «Выберите экран» с поиском и каталогом.
  Выбор заменяет эту вкладку. Уже открытый экран переносится сюда без копии.
  Это работает и при единственной вкладке в исходной группе.
- Поиск получает фокус; Enter открывает первый результат. Пустую вкладку можно
  закрыть обычным крестиком. Состав незаполненных областей сохраняется в раскладке,
  строка поиска — только до закрытия/перезагрузки страницы.
- Новые области создаются только при достаточном месте: текущая группа должна
  вмещать обе части. Проверка и подсказки — в `splitUnavailable` (`app.js`).
  При малой ширине/высоте соответствующая кнопка выключена; в узком режиме
  обе кнопки выключены. Это устраняет переполнение от повторных нажатий.
- «⋯» содержит объединение, закрытие текущей вкладки и «Закрыть группу»
  вместе со всеми её вкладками. Другие группы сохраняются. Заголовка «Активная вкладка»
  и старых четырёх направлений нет. Закрытие сохраняет демо-состояние экранов
  в памяти и ручную сохранённую раскладку. Возврат — «Панели» / «Компоновка».
  Разворачивание активной группы остаётся сверху; Escape возвращает обычный вид.
- **Согласовано 2026-11-02:** «+» открывает такую же вкладку выбора внутри текущей
  группы, включая узкий режим. Выбранный экран заменяет её; уже открытый
  переносится сюда без копии. Старое всплывающее меню «+» удалено.
  Каталог и renderer пунктов общие с верхним меню «Панели». Это открытие экрана;
  создание нового чата/документа будет отдельным действием при детализации сценариев.
- Кнопка инструментов скрывает/возвращает группы, содержащие только инструменты.
  Смешанная группа с чатом не скрывается; в таком случае кнопка открывает инспектор.
  Единственную рабочую группу скрыть нельзя. В узком режиме инспектор — вкладка.
- Меню «Панели» возвращает закрытые панели и фокусирует открытые по стабильному ID.
  Отдельные экземпляры одного примера не создаются.
- Низ содержит пометку Demo, количество вкладок/видимых групп и диагностику.

## Представления

| Представление | Как открыть | Реализация P1 |
|---|---|---|
| Анализ сентября / Сводка по регионам | Рабочая область или «Панели» | Два независимых чата; локальный демо-ответ на ввод |
| Инспектор | Верхняя кнопка, материалы или «Панели» | Mock-контекст с явной привязкой к «Анализу сентября» |
| Итоги сентября / Динамика продаж | Материалы, ресурсы чата, «Панели» | Markdown с одним переключателем исходника; пример графика |
| Браузер | Материалы или «Панели» | Статическая локальная страница без интернет-навигации |
| Файлы | Rail → Файлы | Все mock-источники открывают общий список; реальные файлы не читаются |
| Библиотека | Rail → Библиотека | Карточка одного навыка без запуска |
| Диагностика | Rail, статус или «Панели» | Фикстура журнала, не runtime events |
| Настройки | Правый верхний угол или «Панели» | В P2 добавлены выбор светлой/тёмной темы, палитра акцента и возврат к исходному виду; сохранение раскладки |

Файлы, материалы и библиотека — разные разделы навигации. Чат необязателен:
пресет «Материал и браузер» работает без него. Полные редакторы и состояния
loading/error/cancel относятся к P3.

## Раскладки и состояние

Пресеты в `app.js`: «Чат и инспектор», «Материал и браузер», «Одна группа вкладок».
Dockview сериализует состав, порядок и размеры групп. Автосохранение текущего вида
и ручное «Сохранить / Вернуть сохранённую» используют только browser localStorage
`rnassistant.prototype.dockview.p1`, version 1. Несовместимая раскладка явно
отклоняется с уведомлением; старые preferences прежнего Demo не импортируются.
Вкладки выбора имеют собственный компонент `chooser` и ID `choose-N`; они не
добавляются в каталог продуктовых экранов. Renderer принадлежит оболочке (`app.js`).
В P2 те же preferences содержат `accent` (исходный/палитра) и `theme` (светлая/тёмная).
Смена оформления не пересоздаёт представления и не меняет раскладку.

Черновики, демо-сообщения, режим материала и scroll принадлежат представлению
в `panels.js`, а не его позиции. Они остаются в памяти при закрытии/повторном
открытии и замене раскладки, **но не после перезагрузки страницы**. В localStorage
содержимое чатов не записывается. Числовой scroll при resize может ограничиваться
новой высотой содержимого; полного сохранения смыслового якоря нет.

## Адаптация — In Review

- Широкое окно: дерево и независимые dock-группы. CSS-размеры оболочки — в
  `tokens.css`; стартовая ширина инструментов — в `app.js`.
- До 1000 px: дерево по умолчанию закрыто и открывается поверх workspace;
  выбор представления закрывает его. Пока дерево открыто, workspace inert.
- До 640 px: одна группа вкладок, drag/drop отключён. При возврате к широкому
  окну возвращается прежняя структура с учётом открытых/закрытых вкладок.
- Меню «Демо» задаёт ширину оболочки 900/560/360 px для визуального ревью.
  Это не эмуляция Office task pane.

## Dockview и границы

Используется MIT `dockview-core` **8.8.3**: локальный browser bundle со встроенным CSS.
[Источник, лицензия и хэши](../../prototypes/ui/vendor/dockview-8.8.3/README.md)
хранятся рядом; npm/bundler/CDN и новый loader не добавлены.
Тема использует публичные CSS variables Dockview.

Включён штатный `dndStrategy: 'pointer'`: HTML5 drag не дал переноса в проверенном
встроенном браузере, pointer drag сработал. Меню переноса даёт путь без drag.
Floating и popout отключены; отдельные окна не входят в P1.

## Запуск

Из корня репозитория:

```sh
python3 -B prototypes/serve_ui.py
```

Открыть [Demo P2](http://127.0.0.1:8897/index.html?review=p2).
Это существующий preview-server; assets локальные, внешняя сеть для запуска не
нужна. Прямой `file://` проверялся у прежнего P0; для новой оболочки пока
подтверждён именно HTTP-путь.

## Проверка P2

Проверено во встроенном браузере на macOS 2026-11-02:

- «+» добавляет chooser в ту же группу; поиск, пустой результат и Enter работают.
  Выбор заменяет chooser. Открытый отчёт перенесён между группами без дубликата.
- Новые области справа/снизу используют тот же chooser; исходный экран остаётся.
  При недостаточной высоте нижний split выключается.
- После ревью A/B удалены, базовые CSS tokens восстановлены из P1.
  Настройки акцента проверены при 1080 px: синий акцент в обеих темах, reload
  сохраняет тему и выбор; «Исходный» возвращает прежний акцент. Ошибок/предупреждений
  в консоли нет. Тема и акцент не пересоздают содержимое панелей.
- На 360 px «+» работает, split выключен, поиск получает видимый фокус;
  горизонтального переполнения оболочки нет, body scroll = 0.

Снимки настроек в обеих темах — в [дизайн-системе](UI_DESIGN_SYSTEM.md#оформление-и-акцент).
Это локальный mock-прототип; подробные состояния экранов и Office/WebView2
по-прежнему не квалифицированы.

## Ревью P2 и следующий этап

P1 проверяет постоянный каркас будущего интерфейса: места действий, навигацию,
вкладки и пространство для содержимого. Тексты, карточки и набор полей mock-экранов
не утверждаются вместе с оболочкой. При P3 каркас снова проверяется на реалистичных
сценариях и состояниях; его можно скорректировать по результату. Технические
проверки выполняет агент; от пользователя требуется оценка удобства.

1. Открыть настройки справа сверху: выбрать акцент, затем вернуть «Исходный».
2. Выбрать светлую/тёмную тему: читаемы ли подписи, неактивные вкладки и границы.
3. Нажать «+», найти и выбрать экран; при необходимости повторить на ширине 360 px.

Пользователь выбрал оформление Dockview до A/B и настройку акцента. На ревью —
конкретный вид настроек; поведение «+» согласовано. Следующий этап — P3 небольшими
группами экранов, начиная с чата и инспектора на реалистичном сценарии.
Итоговый handoff пока не создаётся.
