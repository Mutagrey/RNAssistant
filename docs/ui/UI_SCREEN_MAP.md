# Карта экранов, навигации и состояний

## Очередь выполнения — In Review, 2026-11-05

Настройки → Агент: «Одновременно выполняемых шагов (0 — без ограничения)», default 4,
целое 0–64. Tooltip объясняет границу шага и освобождение slots на ожиданиях.
Максимум участников — соседнее независимое поле; общего бюджета выполнения нет.
В ленте обычная строка активности «Ожидаю свободный слот выполнения…» до admission,
далее прежний progress. Stop сохраняется; новые карточки/кнопки/сообщения не добавлены.

## Максимум агентов — In Review, 2026-11-05

Настройки → Агент: «Максимум агентов в совместной работе (0 — отключить)», default 8,
целое 0–64. Tooltip поясняет исходный чат, созданных и приглашённых участников;
1 — только исходный, 0 — отключение. Сохранение/reset идут прежним маршрутом.
В ленте удалена строка «Продолжить общение» для message quota. «+», файлы, сжатие,
восстановление совместной работы и Run controls сохраняют существующее поведение.

## Настройки внутри вкладки — In Review, 2026-11-05

Переход wide → narrow / 125% сохраняет Settings в границах своей Dock-группы.
Выбранный раздел, форма и несохранённые изменения остаются при скрытии/возврате.
Переключение разделов через дерево или компактный select сохраняет прежние routes.

## Пауза и остановка Run — In Review, 2026-11-04

В прежней компактной строке Inbox: «Выполнение приостановлено» и «Продолжить».
Для сохранённого Run после завершения runtime добавляется «Остановить»; для живого
остаётся обычный Stop composer. Сохранённый agents.wait использует прежнее
«Продолжить ожидание» и ту же отмену. Смена Run/ревизии показывает отказ с обновлением,
не управляет новой работой. До receipt обе кнопки disabled; ошибка не стирает черновик.
Открытие/закрытие вкладки ничего не запускает и не останавливает. «+», вложения,
сжатие и выбор нескольких участников сохраняют прежний вход.
[Широкий вид](review/agent-run-controls-wide.png),
[узкий / 125%](review/agent-run-controls-narrow.png).

## Чат внутри вкладки — исправление, In Review, 2026-11-04

Лента и composer остаются в границах собственной Dockview-группы при split,
переходе wide ↔ narrow и 125% CSS zoom. Неактивный чат сохраняет view/черновик/scroll;
возвращение показывает актуальную историю. Открытые вкладки и сохранённая раскладка
не сбрасываются. Проверено на общей presentation Office/Workspace/plugin в Chrome;
Windows/WebView2 остаётся отдельной проверкой.

## Продолжить нескольких участников — In Review, 2026-11-04

В любом чате области: **+ → Продолжить совместную работу…**. Компактное общее меню
показывает сохранённые ожидания в документе/проекте: название и небольшой agent_id,
выбор участников и «Продолжить выбранных (N)». По умолчанию никто не выбран.
«Выбрать показанные», «Следующие чаты» и «Обновить список» используют bounded pages;
выбранные строки остаются видны при смене страницы, максимум 32. Соседняя команда
открывает нужный чат; его вкладка не требуется для продолжения.
После команды каждая строка показывает принятие, изменение состояния или отказ;
неподтверждённый ответ требует обновления списка, без автоматического повтора.
Лента не получает новых сообщений/карточек. Обычное «Продолжить ожидание» остаётся
локальным. Это выбор участников, не уже реализованные именованные группы.
Повторное нажатие «+» из выбора участников открывает обычные действия чата:
файл, Office selection, материал, планирование и доступное по контексту сжатие.

## Universal Browser: toolbar и обсуждение — In Review, 2026-11-05

Страницы остаются вкладками общего Dockview. Строка Browser:
`← → ↻ [аннотация] [сведения · адрес] [▶ </> · чат · экспорт/публикация · версии · ⋯]`.
Правая группа зависит от provider. В фокусе адрес занимает всю строку, инструменты
раскрываются ниже; после ухода фокуса поле сворачивается. Узкая панель открывает
правые controls через ⋯. Подпись «Сохранённый проект…» убрана. Название, версия,
зависимости и хранение открываются по иконке у адреса: «В приложении · CAS» либо
«В папке». Это способ хранения, не публичный доступ и не обещание шифрования.

Saved HTML сохраняет read-only адрес, ▶ / `</>`, file picker и 32K source pages.
Аннотация есть слева у всех providers: работает в живом HTML/plugin, у снимков
недоступна с пояснением. Live preview использует прежние editor controls. Reload живого
HTML читает свежие исходники; изменения других агентов обновляют чистую view, скрытую —
при activate. Dirty buffer сохраняется. Reload сохранённого снимка остаётся exact.
Clock сохранённого HTML доступен и без captured head/при одной версии. Каждое открытие
меню показывает свежую историю документа, включая публикации других чатов. Новую версию
открывает только явный выбор пользователя; текущий снимок и ввод остаются на месте.

Upload плагина вызывает прежнюю guarded публикацию. «Сохранение проекта» у saved HTML
предлагает скачать архив либо создать копию исходников в приложении (P2a, In Review).
Успех открывает workspace; меню затем предлагает открыть тот же проект. Поздний ответ
после ухода из view не меняет навигацию. Отказ допускает новую явную попытку; неизвестный
результат блокирует повтор и предлагает проверить каталог/папку. Исходный снимок сохранён.
Перенос SDK/data/vendor-зависимостей и публикация standalone plugin ещё не реализованы.
«Открыть активную версию» и «Отключить» плагина остаются в ⋯.

«Обсудить» в live/saved HTML или plugin/release открывает связанный существующий
Chat View рядом. Повторное нажатие активирует тот же экземпляр; на narrow чат
активируется в общей группе вкладок. Вложенной панели чата нет. Адресат аннотаций
не меняется при навигации; plugin закрепляет исходный чат после явного открытия.
HTML использует свой exact chatId. Закрытие Browser не отправляет сообщения и
не отменяет Run; аннотации остаются черновиками до отправки пользователем.

Diff скрыт без capability; back/forward видны, но выключены без navigation provider.
Версии показывает только provider с историей. Произвольные URL, browser sessions
ещё в плане. Import добавляет source workspace, без нового session lifetime.
[Широкий вид](review/browser-address-wide.png),
[420 px / 125%](review/browser-address-narrow.png); [процедура ревью](../browser/05_TEST_MATRIX.md#toolbar-review).

## Продолжение ожидания — In Review, 2026-11-04

Живой agents.wait отображается существующей waiting activity. После закрытия runtime
или восстановления чата прежний Inbox banner показывает «Продолжить ожидание», даже
если очередь сообщений пуста. Нажатие явно продолжает тот же Run; открытие вкладки
само его не запускает. Для живого ожидания отдельный pause banner не добавляется.
Переходы и live Stop сохраняют текущие routes; cold Stop добавлен выше.
Windows/Office/WebView2 evidence открыто.

## Совместная работа — Proposed, 2026-11-04

Уточнение пользователя заменяет прежний макет: в ленте только компактная подпись
отправителя (цветной маркер, имя, аккуратный agent_id) и обычное тело сообщения.
Нажатие подписи, включая ID, сохраняет существующий переход к чату отправителя;
копирование и дополнительная кнопка перехода не добавляются.
Получатель, тип «запрос/ответ», message_id и стадии доставки постоянно не показываются.
«Ответ на …» необязателен; обычный ответ может быть понятен из текста. Связь reply_to
для runtime waiting не обязывает отображать отдельную строку в UI.

История и Inbox используют один renderer. Новых зеркальных сообщений поверх send tool
result нет; переписка B↔C не копируется в A. Ошибки и очередь сохраняют существующую
presentation. Расширенная диагностика принадлежит Inspector, не каждой строке ленты.

Inspector ещё проектируется отдельно: сначала компактный список участников с текущим
действием/состоянием, затем детали выбранного участника. Граф общения, граф зависимостей
и время доступны как дополнительные виды по запросу. Их прежний макет не принят.
Факты runtime и сводки модели различаются; закрытая вкладка не делает агента offline,
idle не доказывает completion. Переходы и exact-run Stop используют existing routes.

Production UI этим уточнением не изменён. Полная схема sender→recipient/receipts,
представленная в предыдущем макете, отклонена как шум.

Правка агента в другом HTML не переключает открытый редактор. Для выбранного HTML
новая публикация приходит обычным обновлением состояния; несохранённый код остаётся
до явного обновления исходников. Недоступная публикация показывает recovery без записи.

## Группы в дереве чатов — In Review, 2026-11-05

Пользователь запросил именованные группы и вложенность созданных агентом чатов.
Реализованная структура использует текущую навигацию:

```text
Документ / проект
  Шахматы                         ← группа
    Создать и сыграть             ← обычный чат
      Проверка правил             ← созданный им чат
      Второй игрок                ← созданный им чат
  Другой чат                      ← без группы
```

Группа может содержать и независимо созданные чаты. Один чат в нескольких группах
открывает ту же вкладку; группа не копирует историю. Если создателя нет в этой группе,
дочерний чат показывается на её верхнем уровне. Вне группы действует та же вложенность,
если создатель тоже показан вне групп. Удаление группы/создателя не удаляет дочерние чаты. Членство в группе и
закрытие ветки/вкладки не запускают и не отменяют выполнение.
На документе/проекте — «Новая группа чатов…»; в меню «…» чата — «Группы чата…»
со списком memberships (30 на странице). Пустая группа остаётся доступной в дереве.
Неизвестный результат показывает «Группы недоступны»; обычное обновление перечитывает
состояние, команду не повторяет. У самих чатов нет иконки; внутри группы слева маленькая точка цвета агента.
У группы собственный значок участников, у документа/проекта прежние значки.
Лента/composer/«+» не меняются.

Меню группы: «Переименовать группу», «Удалить группу»; пояснение удаления — «Чаты
сохранятся». Меню чата в группе разделяет «Убрать из группы» и «Удалить чат везде».
Второе использует существующее подтверждение с явным указанием удаления истории
и всех вхождений. После удаления последней связи чат виден под документом/проектом;
после удаления группы её открытые чаты продолжают работать. Общий маршрут открытия
сохраняет одну вкладку независимо от того, из какой группы она открыта.

### Ввод и подтверждение группы — In Review, 2026-11-07

«Новая группа чатов…» и «Переименовать группу» открывают встроенный диалог с полем
«Название группы»; при переименовании текущее имя выделено для замены. Пробелы по краям
убираются, пустое имя и неизменившееся имя не вызывают запись. Enter отправляет форму
один раз; Enter во время IME composition не отправляет. Escape и «Отмена» до отправки
закрывают диалог без команды. Tab/Shift+Tab остаются внутри диалога.

«Удалить группу» показывает её имя и пояснение «Чаты и их история сохранятся».
Начальный фокус — на «Отмена»; удаление выполняется только явным подтверждением.
Имя выводится текстом, включая длинные строки и символы HTML. После отправки controls
блокируют повтор, кнопка «Закрыть» лишь скрывает представление и не отменяет запись.
Ошибку видно внутри диалога и в исходном каталоге; после явного обновления можно открыть
действие заново. Неопределённая мутация автоматически не повторяется.

Закрытие возвращает фокус к актуальной кнопке исходной строки, а после её удаления —
к доступному элементу навигации. Переключение области дерева Office/Workspace
(включая переход в чат плагина) или reset закрывает прежний диалог, не переназначая
его команду. Отображение проверяется с реальным
Dockview, узкой навигацией, длинным именем и масштабом 125%; статус проверки — в
[Migration Plan](UI_MIGRATION_PLAN.md#встроенные-диалоги-групп--in-review-2026-11-07).

## HTML, Библиотека и VBA — In Review, 2026-11-03

«Код»/редактирование текущего HTML открывает вкладку исходного чата. Другой чат
получает свою вкладку, повторное открытие возвращает прежние правки. Выбор файла,
код и страница находятся внутри неё. После смены версии несохранённый текст остаётся;
нужно явно обновить исходники. Закрытие грязного HTML требует подтверждения,
выполняющаяся запись блокирует закрытие. Удаление чата с такими правками блокируется.

«На странице» у отправленной аннотации открывает её исходный чат/плагин. Переключение
активного чата не переносит комментарий или вложение в другой draft.

Библиотека и VBA доступны через rail и выбор экрана «+», перемещаются/закрываются/
восстанавливаются в общем Dockview. В текущем окне закрытие этих retained редакторов
сохраняет черновики. В каждом семействе пока одна вкладка; холодное восстановление
несохранённого кода не обещается. Навигация VBA — общий NavigationPane.

## Общение агентов — In Review, 2026-11-03

С 2026-11-04 сохранённые чаты одного документа/workspace доступны друг другу
независимо от открытых вкладок. Закрытие вкладки сохраняет выполнение, ожидание,
адрес и приём новых сообщений; явный Stop остаётся отдельным действием.
Созданный через `agents.spawn` чат появляется в обычном каталоге без открытия вкладки.
После перезапуска остаётся явное продолжение очереди; закрытый Office target не
подменяется другим документом. Специализированные графы Inspector пока в плане.
Входящее сообщение имеет подпись «Агент a-… · название чата»; нажатие открывает отправителя
обычным маршрутом Dockview. В очереди доступны просмотр и удаление, без редактирования
и «Отправить сейчас». Исходящая tool-карточка содержит адресата, текст и receipt.

С 2026-11-05 число сообщений не ограничивается отдельной квотой; баннер её
продления удалён. Настройки → Агент задают максимум участников (описан выше).
После Stop/перезапуска сохраняется обычное явное продолжение очереди/Run.
Completed со старыми failed/unknown попытками не требует «Продолжить очередь» для
позднего ответа; Failed/Cancelled сохраняют паузу, в том числе `repeated_finish_no_progress`.
В активном run сообщение применяется после текущего model/tool действия, перед
следующим, даже без `agents.wait`. Уже выполняющийся вызов не отменяется.
При `agents.wait` run остаётся активным, шаг показывает
ожидание; ответ будит его, а reasoning/streaming видны в чате получателя без смены фокуса.
Для ревью: открыть три чата с одинаковыми названиями; проверить три ID и `is_self`;
поручить A спросить B/C и ждать, проверить подписи и продолжение того же run; затем
проверить поздний ответ после окончания хода и явный Stop. Максимум 1 — проверить отказ приглашения второго участника.

| Настройки | Singleton Dockview view S1c; вход снизу rail, повторное нажатие активирует существующую вкладку |
| Диагностика | Singleton Dockview с разделами Запуски/Lab/Приложение; сохранённый Запрос — отдельный singleton |
| «Запросы N» в нижнем status bar | Работающие запросы Office/Workspace/plugin текущего runtime; строка открывает exact чат, отдельный Stop отменяет exact run без открытия вкладки |

Chooser использует компоновку Demo, показывает «Ничего не найдено» при пустой выдаче.
В контрольной точке Chat View (In Review) он включает чаты доступного Office/Workspace
каталога: выбор открывает target в этой группе или переносит уже открытый экземпляр.
«+» остаётся выбором экрана, не создаёт новую domain-запись чата.
Открытие чата из дерева сохраняет остальные вкладки. Разные чаты можно видеть рядом;
input/model/edit/scroll принадлежат каждому. Inspector следует фокусу в чате.
Выбор Office-чата текущего документа сразу показывает нужную вкладку, даже пока
native selection ждёт своей очереди. Выбор другого документа сохраняет native
проверку привязки. Закрытие вкладки во время загрузки и позднее фоновое обновление
не открывают её снова; старый ответ не меняет более новый выбор пользователя.
Отправка и поток одного чата не блокируют дерево и ввод другого чата. Повторный
клик «Предыдущие» разделяет pending read; последующее «К последним»/«Предыдущие»
имеет приоритет над старым ответом даже при той же revision и позиции истории.
Новый пустой чат показывает общее приветствие с акцентной иконкой Demo.
В низком split оно читается прокруткой от начала; подсказка заполняет composer
своего чата, первое сообщение заменяет приветствие и возвращает обычный follow.
Close/reopen/restore не изменяют document/session ownership и не останавливают run.
Закрытый чат остаётся в нижнем меню до завершения запроса. Stop показывает
«Остановка…» и блокирует повторное нажатие до ответа; устаревшая строка не отменяет
новый run этого чата. Empty/error и повторное чтение отображаются явно; ошибка Stop
не исчезает от фонового обновления списка. Escape возвращает фокус в кнопку меню.

Workspace/plugin прикрепляют файлы в общие карточки composer, включая отправку во
время run. При Queue сообщение сохраняется до следующего хода; доступны общие
редактирование, удаление и «Отправить сейчас». После Stop очередь ждёт явного
«Продолжить очередь». Неприменённое уточнение старого run не воспроизводится в новом;
его текст можно явно вставить в ввод. Поздний upload/ACK меняет только свой черновик.
Старая раскладка единственного `conversation` без target явно сбрасывается с
уведомлением; история и черновики не мигрируют и не удаляются.
«Панели» — компактное меню подключённых видов с отметкой уже открытого.
Общие меню поддерживают Arrow Up/Down, Home/End, Tab, Escape/возврат focus.
StatusBar показывает mode/connection и раскладку только при видимом workspace;
агрегация фактических фоновых operations ещё относится к последующим срезам.
Его кнопка диагностики целиком помещается в нижнюю строку; длинный материал
прокручивается внутри своего view, сохраняя положение StatusBar.

Текущие ID: `chat:<encoded source/workspace/session>` (один экземпляр на exact chat),
`conversation` (пустое стартовое состояние), `inspector`
(четыре настоящих раздела context/abilities/usage/activity), `settings`, `request`, `diagnostics`.
`choose-N` — временный
элемент Shell, не продуктовый экран и не второй каталог. Незавершённые chooser tabs
сохраняются вместе с layout; поисковая строка — только в памяти view.

Rail пока переключает прежние sections; их переходы, lazy render и deactivation
остаются у `switchTab`. Целевой принцип Demo «навигация меняет дерево и не закрывает
вкладки» сохраняется: разделы скрывают рабочую область, но не уничтожают её.
Все разделы внутри Dockview этим срезом не объявлены перенесёнными.

При узкой рабочей области группы собираются во вкладки. Широкая раскладка
возвращается при расширении; закрытая в узком режиме панель не воскресает.
Split недоступен, если обе части не помещаются. Точные пороги S1b In Review,
проверяются по ширине рабочей области, а не копируются из Demo без учёта дерева.
Native plugin preview и Office HTML preview пока сохраняют прежнее размещение;
их верхний контрол общий, iframe/session не пересоздаются из-за chat docking.

Подтверждённое направление S3b (после завершения S3a): plugin preview открывается
отдельным view рядом с общим Chat View или в другой группе. Открытие/закрытие
предпросмотра не подменяет чат; выбираются и перемещаются независимо. Старый
связанный toggle/splitter удаляется в этом срезе. Пока это план, не текущий placement.

## Боковая навигация — поведение Demo

Owner — `RNAssistantShellLayout` в `app-layout.js`, единственный владелец режима,
видимости, ширины и закрытия. Перенос по прямому запросу пользователя 2026-11-02.

- При ширине Shell больше 1000 px дерево занимает место рядом с рабочей областью.
  Предпочтение открыть/свернуть и изменённая ширина сохраняются.
- Все разделы используют один диапазон ширины и splitter из общих tokens.
  Стрелки изменяют ширину; Home/Enter/двойной клик восстанавливают исходную,
  End раскрывает до максимума. Перетаскивание ограничивается диапазоном;
  сворачивание остаётся у кнопки Shell/повторного клика раздела.
- До 1000 px дерево изначально скрыто; открывается поверх содержимого с подложкой.
  Полоса разделов остаётся доступной, рабочая область временно `inert` и не сжимается.
- Нажатие другого раздела показывает его навигацию; повторное нажатие активного
  переключает её видимость. Верхняя кнопка делает то же для текущего дерева.
- Выбор экрана мышью, Enter или Space закрывает временное дерево; раскрытие папки,
  поиск и действия внутри узла его не закрывают. Фон и Escape закрывают дерево.
  В широком режиме выбор экрана сохраняет дерево открытым.
- Фоновая смена selection не захватывает фокус. Выбор/создание чата из навигации
  сохраняет клавиатурное продолжение в дереве. Действия строки видны при наведении
  и фокусе без изменения размеров строки; на touch остаются доступны постоянно.
  Справа от названия нет постоянного пустого резерва; длинное название прокручивается
  внутри строки при наведении/клавиатурном фокусе. Направляющих линий у вложенности нет.
  Повторная отрисовка с тем же выбором сохраняет прокрутку дерева; новый выбор
  показывается в области видимости.
- Кнопка нового чата создаёт сохраняемую пустую запись; к ней можно вернуться при
  активном ответе в другом чате. Автоматический пустой черновик исчезает из дерева
  при уходе с него.
- Переход между компактным и узким режимами не теряет текущее временное открытие.
  Возврат к широкому окну восстанавливает отдельное широкое предпочтение.
- До 640 px Dockview собирается в одну группу и отключает drag/split; при расширении
  возвращает широкую раскладку. Дополнительное ограничение по доступному месту
  сохраняется для слишком узкого workspace даже в широком окне.

Кнопка инструментов не закрывает вкладки отдельной группы Inspector, а скрывает её.
Размер, положение и DOM сохраняются. Смешанная группа с чатом не скрывается;
Inspector в ней активируется. Единственную видимую рабочую группу скрыть нельзя.
Крестик и «Закрыть группу» остаются отдельными командами фактического закрытия.
HTML/plugin preview пока управляется прежним adapter через общий верхний контрол.

JSON-профиль на странице «Агент»: формат ответа → краткое описание истории →
уведомление миграции при наличии → раскрываемый пример ответа/следующего запроса.
Пример отражает черновик; применение только после ACK. Native-варианты находятся
в лаборатории; отдельные verdict для содержимого, связи, видимости ID и native-цикла.

## Настройки и меню rail S1c

- Gear открывает настройки в группе чата; повторное нажатие активирует существующую
  вкладку на её текущем месте. «+» и «Панели» используют тот же descriptor.
- Поиск и категории перемещаются вместе с формой. При недостатке ширины группы
  тот же список разделов доступен через компактный select. Глобальное дерево
  документов/проектов остаётся независимым; gear не переключает его open/closed.
- Крестик/закрытие группы спрашивает о dirty форме; «Отмена» оставляет всё на месте,
  подтверждение закрывает вкладку с сохранением правок в памяти до перезапуска.
  «Применить» — существующее действие сохранения. Pending save блокирует закрытие;
  ошибка и новые правки во время запроса остаются видимыми и неприменёнными.
- Наведение на gear показывает шесть разделов и версию; выбор открывает нужный
  раздел единственной вкладки. У остальных rail buttons сохранены подписи,
  у plugins — существующие действия. Короткая задержка hover убирает случайные
  открытия и запросы при пересечении полосы курсором.
- В меню можно перейти курсором через зазор, Tab/стрелками — с клавиатуры.
  Escape закрывает его и возвращает фокус без повторного открытия. Уход курсора
  закрывает подсказку; устаревший async plugin response не заменяет новое меню.

## Модель чата S2a

Маршрут: существующий composer → выбор модели, в том же `conversation` view.
Office, project и plugin source показывают одинаковое меню: default, сохранённая
модель вне каталога, каталог с общими badges. Отдельная вкладка/форма не создаётся.

| Состояние / действие | Общее поведение |
|---|---|
| Явный выбор | Сохраняется в exact chat; остальные чаты и глобальный default не меняются |
| По умолчанию | Сохраняется отсутствие override; следующий run берёт текущую общую модель |
| Сохранение / ошибка | Отправка ждёт ACK или read-back при потерянном ответе; подтверждённый отказ сохраняет прежнюю модель, draft не меняется |
| Переход A → B | Поздний ответ A не меняет controls/draft B; возврат читает сохранённый выбор A |
| Running / approval | Выбор заблокирован; принятая модель закреплена за run |
| Каталог настроек | Неприменённые возможности/preview не меняют composer; Apply действует после ACK |

Остальные общие функции чата не должны иметь самостоятельный UI по типу host.
Ресурсы, инструменты и разрешения предоставляет domain adapter; оставшиеся
различия attachments/context перечислены в Migration Plan, не считаются устранёнными.

## Полный реестр основных областей и подэкранов

### Общая навигация и независимые объекты — Proposed, 2026-11-02

Материалы, Библиотека и будущие Файлы — источники одной панели навигации Shell.
У источников разные данные и действия; заголовок, поиск, фильтры, состояния,
дерево/список и открытие объектов используют общие компоненты. Переключение
источника не закрывает рабочие вкладки и не заменяет их содержимое.
«Все материалы» остаётся обзором каталога, а не ещё одним viewer.

Сначала экраны раскладываются по общим семействам; частный экран получает
поведение композицией этих элементов, сохраняя предметного владельца:

| Семейство UI | Конкретные consumers | Общая часть / предметная граница |
|---|---|---|
| Навигация/каталог | Материалы, Библиотека, каталоги чатов/проектов; будущие Файлы | Tree/list, поиск, scope, paging, действия строки; состав и queries у adapter |
| Просмотр объекта | Материалы разных форматов, HTML/plugin, точные тела диагностики | View instance, source/status/actions, ViewerRegistry; provider/read scope различаются |
| Редактор/форма | Prompt/skill/tool, HTML code, VBA, Settings | Dirty/save/error/close contract и общие forms; validation/save остаются предметными |
| Разговор | Office/Workspace/plugin chat | Один conversation UI и lifecycle; host capabilities и runtime address различаются |
| Операция/наблюдение | Запуск, журнал, Model Lab, проверки хранилища | Общие состояния, Progress/OperationView, таблицы/детали; запуск/отмена/исход принадлежат service |
| Инспектор | Контекст и детали выбранного объекта/запуска | Явный target, детали и deep links; не отдельное хранилище или UI-вычисление authority |

Это семейства поведения, не шесть новых базовых классов или один универсальный
renderer. Внутренние предметные экраны standalone plugin остаются приложением
плагина; их переносимость не означает второй host Shell или второй chat UI.

Схема широкого экрана (компоновка — действующий Demo/Dockview):

```text
Rail | Источник: Материалы   | Группа A: [Отчёт.md] [Данные.json] | Группа B: [HTML] [Плагин]
     | scope / поиск / меню | выбранный format viewer           | общий browser surface
     | дерево или список    | действия выбранного объекта       | действия его provider
```

В узком режиме существующий Dockview собирает группы во вкладки; navigation
открывается прежней кнопкой Shell. Вкладки сохраняют свои target и состояние;
preview не перекрывает чат собственным overlay/splitter. Inspector следует
явно выбранному объекту только там, где такой режим реализован; не притворяется
универсальным инспектором данных автоматически.

| Маршрут | Ожидаемое поведение |
|---|---|
| Материалы → Markdown → PDF → назад к Markdown | Две независимые вкладки; прежняя прокрутка Markdown и страница PDF сохранены; дерево сохраняет фильтр |
| Материалы → HTML; затем plugin из rail | Общая browser presentation, два разных target/provider; у плагина остаются его права, публикации и связь с source chat |
| Библиотека → навык/инструкция/инструмент | Предметные details/editor через тот же open route; просмотр не включает объект в чат. Несохранённая правка защищена своим owner |
| Чат → материал → смена активного чата | Вкладка остаётся на прежнем exact document/object/revision с видимой подписью источника |
| Повторно открыть тот же объект | Активировать уже открытую вкладку. Явно выбранная другая версия — отдельный target |
| Файлы → документ | Будущий adapter к разрешённому root и typed paged API; сегодня такого product screen/контракта ещё нет |

Действия различаются: открыть просмотр, редактировать, подключить к чату,
скачать, удалить. В частности, `select` каталога больше не должен скрыто вызывать
изменение active artifact/link. Этот переход поведения входит в миграцию, не
объявляется уже исправленным. Для недоступного/удалённого объекта вкладка явно
показывает состояние, не подменяет его текущим выбором дерева.

Общий Browser — просмотр разрешённого HTML/provider, не произвольный интернет-браузер.
JSON/Markdown/source переключаются внутри viewer; PDF/image получают свои controls.
Разные места открытия одного target используют один route и одну реализацию.

Целевой ID — presentation identity, не URI/authority runtime. В первом срезе
conversation singleton; параметризованные chat IDs ниже — последующая цель.

### Навигация S3b.1 — In Review

Материалы и Библиотека используют один header: название → поиск → «+»; поиск
раскрывается на месте названия, Escape очищает фильтр и возвращает фокус кнопке.
Ни поиск, ни выбор материала не подключают его к чату. Таблица каталога и дерево
ведут через один material target route; «Подключить/убрать», «Использовать в чате»,
«Редактировать» — отдельные действия существующих owners. Для неактивного HTML/
плана прежний редактор требует явного «Использовать в чате»; это ограничение
singleton editor до следующих срезов, а не побочный эффект просмотра.

Loading/error/retry/paging находятся под деревом. При достижении 500 материалов
показана причина ограничения и предложение уточнить поиск. Удаление открытого
материала возвращает к каталогу; фильтрация сохраняет открытый материал.
Узкую навигацию открывает общий toggle Shell: отдельный mobile layout Материалов
и прежний лимит высоты дерева 150/180 px удалены.

VBA, документы/чаты, проекты и будущие Файлы используют ту же модель подключения;
очередь и пределы — [таблица S3b/S4](UI_MIGRATION_PLAN.md#s3b-общая-навигация-и-независимые-просмотры--proposed).

### Независимые материалы S3b.2 — In Review

Rail Материалы открывает каталог в основной Dock group. Дерево/таблица и chat card
открывают один `material` view по actor chat + document + exact URI; повторный target
активирует существующую вкладку, новая revision открывается отдельно. Header показывает
название и исходные документ/чат/версию; format viewer содержит readable/source/JSON
и свои контролы. Меню содержит download/copy-link/reload и доступные команды Catalog.
Фильтр, переключение чата или выбор другого источника не меняют сохранённый target.
Выбор rail Чат показывает conversation; вкладки материалов остаются рядом и доступны.

Ready view сохраняет свой DOM/mode/scroll на возврате, move и restore текущего окна.
Loading отменяется при hide; поздний lease закрывается; ошибка показывает retry.
Unknown/слишком большой формат имеет объяснение и доступ к оригиналу. Текст читается
по 32 000 chars (последние 16 страниц), full readable ≤512 000, image preview ≤8 MiB;
PDF сохраняет имеющиеся page/thumbnail limits. Не более шести material views.
Download использует streaming save при поддержке browser API; fallback ≤8 MiB с
явной причиной отказа. Восстановление после перезапуска возвращает target, но пока
не mode/search/scroll специализированного viewer.

S3b.3a вынес live HTML preview в Browser; S3b.3b открывает сохранённые HTML-проекты
в адресных вкладках. Raw HTML file
пока показан инертным исходником. Library и VBA editors — S4. Эти ограничения
не заменяются дополнительными browser/chat UI. [Ревью](UI_MIGRATION_PLAN.md#s3b2-независимые-просмотры-материалов--in-review-2026-11-02).

## Сквозная навигация — предлагаемое поведение

1. Rail выбирает контекст левой навигации. Выбор leaf вызывает общую команду
   открыть/активировать view; не создаёт его копию при перемещении.
2. «+» выбирает экран в текущей группе; split right/below создаёт область с выбором.
   «Закрыть группу» закрывает только её views, не отменяет domain runs.
3. Чат → материал открывает resource identity; чат → подробности запуска передаёт
   owner/session/run/event. Inspector следует выбранному conversation; pin
   требует отдельного согласования и видимой подписи scope.
4. Закрытый view восстанавливается из навигации. Runtime и черновик не принадлежат
   Dockview JSON. Неверные сохранённые layout entries сбрасываются явно и локально.
5. При узкой ширине сначала сворачивается navigation, затем группы становятся
   вкладками. Конкретные пороги Demo не утверждены как production thresholds.
6. Материалы, библиотека, diagnostics, plugin работают при скрытом Chat View.
   Настройки доступны снизу слева; управление областями вынесено наверх.

## Запуски — In Review, 2026-11-03

Кнопки диагностики в rail и status bar открывают текущий чат и его последний
известный запуск, сбрасывая прежнюю выборку. Нажатие самой Dock-вкладки или
возврат через «Панели» сохраняет источник и выбранный элемент.
В деревьях Office/проектов/плагинов действие «Диагностика чата» открывает выбранный
источник без смены текущего composer. Верхняя строка document/project + chat —
ссылка обратно в этот exact чат; технические IDs доступны в tooltip.
Переход из ответа: «Открыть ход работы» → «История и диагностика» в Inspector
сохраняет конкретный run/step. Повторного заголовка
«Диагностика» и кнопок возврата к другим Dock-вкладкам внутри нет.
Рядом с document/chat scope находится «Все запуски»: снимает ограничение запуска,
шага или события и показывает дерево того же чата. Страницы читаются через «Ещё».
Строка группы выбирает объект и переключает раскрытие; повторное нажатие сворачивает
ветку. Стрелка меняет только раскрытие; Enter/Space повторяют действие строки.

| Выбор | Один reader рядом с деревом |
|---|---|
| Запуск | Итог, число запросов/действий; сводка запросов с исходами и результатами инструментов |
| Запрос | Запрос и ответ со временем/состоянием, действия с target и результатом; переход к полному составу запроса |
| Действие | Итог, target, результат или аргументы в общем JSON viewer |
| Событие | Время/номер, пояснение, данные или связи; тело загружается явно |

Основная группа — обмен запрос/ответ; повторная попытка является отдельным запросом.
У повтора в названии видна причина, в reader — feedback и кнопка исходного ответа
модели. API retry явно отличается от format repair/отклонённого finish и входящего
сообщения. Фильтр «Попытки и отмены» включает такие запросы. Если исходный ответ
не загружен или отсутствует, reader говорит об этом явно. В полном запросе доступны
отправленная корректировка и фактический timeout из сохранённых настроек.
Технические «шаг начат/завершён», chunks и verdicts собраны в свёрнутые служебные
группы; отдельного уровня «Модель» нет. Отсутствующая связь явно остаётся
«Без привязки…»; соседство событий не создаёт корреляцию. Обзор выбранной группы
показывает результаты сразу, без второго дерева; строки ведут к существующим
объектам. Длинный обзор открывается порциями по 30 строк. На узкой вкладке дерево
располагается над деталями, «Открыть запрос» находится в строке заголовка reader.
При загрузке область чтения сохраняет размер. Повторный вход в ту же pending
выборку не начинает чтение заново. Refresh/ошибка следующей страницы сохраняют
загруженный журнал; ошибка видна в строке состояния. Другой источник очищает reader.
Выбор, раскрытия и фильтр сохраняются при возврате из Запроса и reopen;
move/split/restore не пересоздают дерево.

## Структура запроса — production, 2026-11-02

Пользователь попросил сначала продумать переработку: компактный состав запроса,
удобное чтение сообщений как Markdown/JSON. [Макет содержимого](review/request-structure.html)
использует production tokens, NavigationTree и viewers; не копирует Shell/Dockview.
После проектирования пользователь поручил production, commit и push. Ниже — реализованная структура; макет сохранён как история решения, не второй production path.

**Одна вкладка «Запрос Q…»** из чата, Inspector или журнала. Видимый scope:
документ/проект → чат → запуск → попытка. Первый срез — singleton request view;
смена чата не подменяет открытый запрос. Если host больше не даёт доступ к его
источнику, показывается недоступность. Несколько живых запросов требуют отдельного
scoping. Правая панель Inspector сохраняет роль рабочего контекста чата.

Три задачи: **Состав / Ответ / Изменения**. В Составе — локальное оглавление слева
и один reader справа, вместо семи tabs и цепочки вложенных details. Первый выбор —
Обзор: состояние/причина, frozen settings и API usage. Число сообщений видно в оглавлении, сохранённая оценка — в группе/строках. Обзор не читает тело. Полный реестр ресурсов/доказательств доступен узлом
оглавления, конкретные связи — у сообщения/ответа через существующие readers.
«Исходник запроса» всегда доступен в меню действий запроса в его шапке.

| Узел / действие | Содержание |
|---|---|
| Разделы сообщений | Только записанные группы RequestComposition: инструкции и каталог, история, вызовы/результаты, ресурсы и прочие присутствующие группы. Число сообщений и ≈ токены |
| Сообщение | Номер в исходном массиве, роль, подсказка с фрагментом после чтения тела, записанная оценка. Тип и признак исторической проекции/результата — в reader. Вся строка выбирается, содержимое сразу появляется в reader |
| Порядок отправки | Другой порядок того же списка с сохранением selection; группировка не выдаётся за порядок wire |
| Параметры и формат | Точные сохранённые поля запроса; frozen settings отдельно в Обзоре. Формат нового ответа независим от истории. Native tools — отдельный узел только при наличии такого поля в запросе |
| Не отправлено | Записанные пропуски и причины; отдельно от messages и суммы отправленного контекста |
| Источники | Кратко «откуда / в каком виде отправлено», затем точные recorded facts и переход к локальному оригиналу/ресурсу. Без достраивания неизвестных связей |

Не более двух уровней: раздел → сообщение. Части составного content выбираются
в reader, не добавляют цепочку раскрытий в дереве. Смешанная инструкция остаётся
одним сообщением, пока compiler не записывает точные границы навыков/правил.
При отсутствии классификации явно показывается порядок отправки и причина.
Заголовки/числа групп доступны из metadata; тело читается при выборе сообщения,
параметров или исходника. Поиск в текстовом viewer ограничен выбранным сообщением. Общий поиск по сообщениям и фильтр роли остаются вне этого среза; группы и страницы доступны без чтения других попыток.

**Форматы выбранного content:**

- Markdown — существующий безопасный renderer полного текста.
- JSON — общий lossless viewer. JSON внутри строки разбирается только по выбору
  пользователя, с подписью «JSON в строке · в запросе string». Это представление,
  не изменение типа и не повторная проверка model protocol.
- Текст — декодированный string без Markdown; это не исходные байты JSON-конверта.
- «Точное сообщение JSON» — сохранённый JSON сообщения с role/content/tool_calls,
  точными типами/escape. Общий исходник запроса остаётся отдельным действием.

Над содержимым всегда видны область и тип, например `messages[4].content · string`;
историческая проекция и результат инструмента подписаны отдельно. Невалидный JSON
в режиме чтения не означает отказ runtime. Неполный текст не рендерится как полный
Markdown; обрезка/скрытие секретов/отсутствие данных видны. Медиа открываются lazy.
Копирование называет область: содержимое, JSON сообщения или весь запрос.

На узкой **группе Dockview**, независимо от окна: список → detail → «К составу»,
с прежними scroll/focus. На широкой — две колонки без нового drag/splitter.
Tree сохраняет общую клавиатуру, формат — selection и bounded presentation state.
Deep link сразу показывает нужное сообщение/поле и страницу.

Ревью макета: «Открыть сообщения» → Markdown/Текст; выбрать результат чтения →
JSON → меню сообщения → «Точное сообщение JSON»; меню запроса → исходник;
переключить порядок; сузить; выбрать неполную запись.
Response/diff представлены краткими синтетическими состояниями, не новым runtime.
Макет не доказывает production routes, async cleanup или performance.

После уточнения пользователя scope кнопок/меню — **вся диагностика и используемые
ею общие компоненты**, не все экраны приложения. Размещение действий:

| Уровень | Действия и место |
|---|---|
| Shell / Dockview | Раздел диагностики в rail; вкладки/закрытие/move/split/maximize принадлежат workspace. В содержимом запроса нет второй копии placement-кнопок |
| Разбор запуска | Выбор запуска, фильтр и follow рядом со списком событий; экспорт/редкие операции в одном меню этого списка |
| Запрос | Scope в шапке; точный исходник/download/refresh/export в её ActionMenu; Состав/Ответ/Изменения — общий EditorTabs, не ряд обычных кнопок |
| Сообщение | Локальный заголовок и меню с полным сообщением/источниками. Markdown/JSON/Текст — единый segmented control; он не выглядит ещё одним уровнем навигации |
| Viewer данных | Поиск/копирование/сворачивание относятся к показанным данным. Одно место для каждого действия; общий viewer сохраняет свой standalone режим |
| Лаборатория | Endpoint/сценарий и явные Запустить/Остановить рядом; скачивание отчёта у действий сценария. Открытие view не запускает сценарий |
| Приложение | Фильтры рядом с журналом; операции обслуживания — у состояния хранилища. Действия изменения данных не смешиваются с навигацией и выбором формата |

В narrow первыми сохраняются выбранный объект, основное действие и переход назад;
редкие действия остаются в том же меню, не копируются в отдельный mobile toolbar.
Popup портальный через ActionMenu: внутри viewport, без обрезки границей Dockview,
Escape возвращает фокус, смена scope/deactivate закрывает меню.

## Общая матрица состояний

При отложенной загрузке истории дерево показывает «Загрузка чатов…»; Настройки
доступны и при раскладке без Chat View. После подтверждения удаления строка чата
показывает «Удаление…» уже во время ожидания очереди. Повторное удаление и выбор
этой строки заблокированы до ответа. Строка исчезает только после ответа native;
при ошибке остаётся, причина записывается в журнал приложения.

Лента, 2026-11-03 (In Review): короткое принятое `reason` видно возле действий;
оно и `message` сохраняются после finish и повторного открытия чата. Сворачиваются
только детали действий. Пустой `message` не создаёт сменяющийся placeholder.
«Оценка модели и источники» объединяет claims и счётчики, изначально закрыта;
отдельной жёлтой карточки unknown/partial и дублирующего предупреждения над вводом
нет. Ошибка/отмена остаются видимыми; совпадающая diagnostic row заменяет второй
баннер. Штатный возврат макроса подписан «Вызов завершён», непроверенный эффект
указан внутри раскрытия и не становится verified change.

Уточнение ленты/очереди: два отдельных отправления одинакового текста после ACK
показывают два ввода. При применении очереди bubble остаётся до exact message ID
в истории; очередная пересекающаяся страница не удаляет его из загруженного окна
(cap 240 сохранён). «Черновик ответа · …» отличает текущий поток от принятого
сообщения; переход live → saved сохраняет идентичность сегмента и принятый текст.

Project/plugin Stop сразу показывает «Останавливаю запрос…». При устаревшем cursor
обновляет этот чат и повторяет отмену один раз, только для прежнего run и view.
Смена запуска, terminal state или уход из view исключают повтор; неподтверждённая
доставка показывает ошибку. «Отмена запрошена…» ещё не означает terminal cancellation.

| Состояние | Что обязан увидеть пользователь | Реальный owner / проверка |
|---|---|---|
| loading / empty | Локальная загрузка или отсутствие объектов, не success | Query owner; проверять cold/warm и пустой каталог отдельно |
| dirty / preparing / saving | Изменения ещё не подтверждены; draft не очищается заранее | Draft/resource/settings owner; reject/late receipt |
| queued / running / waiting | Фактический run/operation и доступные действия | Kernel/conversation events; без искусственных процентов |
| cancellation requested / cancelled | Запрос отмены отличается от подтверждённой остановки | Run/operation owner; не прекращать run при закрытии UI |
| failed / unavailable / unknown | Причина, сохранённый ввод, безопасное следующее действие | Exact scope; не выводить success из transport ok |
| stale / switched / disposed | Старый ответ не меняет другую вкладку | generation/revision/identity; cleanup observers/leases |
| narrow / zoom / keyboard | Доступны ввод, menu, focus и recovery закрытого вида | Browser + позднее реальный WebView2; фото с Windows |

Это source inventory всех основных экранных семейств и их перечисленных режимов,
а не утверждение, что каждый runtime-сценарий воспроизведён. Непроверенные размеры,
focus transitions, performance и host behavior остаются gates Migration Plan.

### Маршруты Browser S3b.3a — In Review

- HTML текущего чата → «Открыть просмотр» → вкладка HTML. Редактор Материалов
  показывает ссылку на просмотр вместо второй iframe-панели.
- Плагин в rail → вкладка его просмотра; выбранный чат и черновик сохраняются.
  «Чат исходников» открывает обычный Conversation view. Переходы по дереву исходных
  чатов не переключают Browser и не создают новую plugin instance.
- Inspector и Browser — отдельные вкладки: можно разместить рядом; переключатель
  инспектора содержит только Контекст/Возможности/Токены/Текущий запуск.
- Перенос/restore/переключение Office–Workspace–Материалы сохраняют iframe document
  в текущем окне. Close закрывает instance/leases; повторное открытие начинает новую
  сессию просмотра, разговор продолжает выполняться независимо.
- После смены текущего HTML source прежний live Browser показывает причину и путь
  обратно к Материалам. После холодного старта выбор источника явный.

Ограничение одного live HTML/plugin относилось к S3b.3a; S3b.3c заменил их
адресными views. Library/VBA размещены в Dockview, но пока сохраняют по одному editor owner.

### Маршруты сохранённых Browser objects S3b.3b — In Review

- Материалы: таблица/дерево/карточка чата → адресная вкладка HTML по chat/document/URI.
  Второй документ/версия открывается рядом; повторный выбор возвращает прежний view.
  Фильтр источника, смена чата и несохранённые правки редактора не подменяют его.
- «Страница / Исходник» переключает presentation; выбор файла и страницы текста не
  пересоздаёт iframe. Сохранённый код не зависит от live editor. Данные — снимок при
  открытии, согласно export policy. Действия редактора доступны явно через material owner.
- Меню версий материала открывает отдельный exact URI. История доступна при наличии
  Library head metadata; отсутствие metadata не выдаётся за пустую историю.
- Плагин → «Версии» → отдельный pinned release, даже для текущей публикации. Это пробная
  копия данных. Workbench/candidate и выбранный чат не переключаются. Меню версии →
  «Восстановить эту версию» с CAS guard. Успех не заменяет открытый сохранённый preview;
  конфликт показывает причину. Редактируемые исходники остаются прежними.
- Pending hide/close освобождает поздний ответ; ready hide сохраняет iframe/input.
  Reload и close/reopen начинают новый просмотр. Ошибка/лимит имеют видимую причину,
  reload и доступ к оригиналу. Метаданные и открытие экранов не запускают модель.

В 420 px / 125% те же Dock tabs и общая панель действий переносятся на строки;
Enter с placeholder вводит в содержимое, меню возвращает фокус по Escape. Результаты
и ограничения: [S3b.3b](UI_MIGRATION_PLAN.md#s3b3b-точные-сохранённые-browser-targets--in-review).


### Уточнения по фото: плагины и материалы — In Review, 2026-11-03

- Rail плагина открывает его собственную вкладку; повторный выбор возвращает её.
  Выделение следует активной Dock-вкладке. Выбор плагина не меняет текущий чат.
- В форме создания/оформления одно поле названия плагина находится сверху, каталог
  иконок раскрыт постоянно. Повторной шапки и разделителей между полями нет.
  Новый выбор иконки начинает с исходных цветов SVG; палитра показывает выбранный
  цвет. «Добавить готовый SVG» раскрывает отдельные «Название SVG» и код;
  «Добавить SVG» сохраняет и выбирает иконку, затем сворачивает ввод.
- Материалы: документ с настоящим названием → чат исходной версии HTML → проекты.
  Остальные материалы находятся в документе; подключение к текущему чату — metadata,
  не отдельная дублирующая ветка. Неизвестный source chat не угадывается.
- Одно меню «…» в строке дерева содержит подключение/исключение и удаление по прежним
  guards. Удаление из документа сохраняет подтверждение; исключение меняет лишь связь.
- «Исходник» открывает readonly CodeMirror с номерами строк и подсветкой; текущий
  редактор вызывается отдельным действием. Код заполняет оставшуюся область без
  внешней рамки/отступа, с общим фоном в обеих темах. Страницы и лимиты сохраняются.

Live HTML scoping закрыт следующим срезом, описанным в начале документа.
Независимые Library/VBA object owners и Windows qualification остаются открытыми.
