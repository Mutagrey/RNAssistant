# RNAssistant — Visual Inspector & Annotator: план для агента

Статус: проектное ТЗ. **Перед изменением кода провести аудит актуального репозитория.** Не считать приведённые ниже имена файлов и API существующими.

## Цель и UX

Пользователь открывает HTML из библиотеки/workspace, UI плагина или (на следующем этапе) UI RNAssistant в существующем WebView2 preview. Включает Annotate, наводит курсор (рамка вокруг DOM-элемента), кликает, пишет комментарий. В composer чата добавляется чип `a1` с аннотацией; можно добавить `a2`, `a3`, редактировать и удалить их. При отправке агент получает структурированные ссылки, определяет исходный HTML/CSS/JS, делает изменения **штатными инструментами проекта** и проверяет результат. Дополнительный режим Inspect позволяет прикрепить выбранный элемент `e1` без комментария для диагностики.

## Обязательная инструкция агенту

1. Изучи текущий код RNAssistant: WebView2, HTML preview, JS↔C# bridge, resource/CAS/workspace, Context Explorer, формат ссылок `r1@…`, composer, session/event log, tools/skills registry, файловые операции и патчинг. Прочитай последние архитектурные ADR/планы.
2. Сохрани аудит в `docs/architecture/visual-annotator-audit.md`: конкретные пути и функции, существующие контракты, точки интеграции, риски, что переиспользовать. Проверь противоречия с этим ТЗ.
3. Подготовь краткий ADR: минимальная реализация на JS, варианты интеграции, схема ресурсов, жизненный цикл, доверенные границы. Если проект уже имеет подходящий механизм, **не создавай второй**.
4. Составь план изменений по файлам и тестам. Реализуй по фазам, не проводя несвязанный рефакторинг. Документируй решения и реальные результаты тестов.
5. Если агент работает в Linux и не может запустить WebView2/Excel, тестируй JS отдельно, а Windows end-to-end явно помечай как непроверенный; не объявляй интеграцию завершённой.

## Архитектура и ответственность

- **Inspector JS**: `activate/deactivate/dispose`, hover, overlay, выбор DOM-элемента, ограниченный snapshot. Никакой работы с LLM, файлами и историей чата. Используй pointermove, elementFromPoint, getBoundingClientRect, capture click, scroll/resize listeners. Overlay не должен менять layout или перехватывать клики вне режима.
- **Annotation controller/store**: create/update/delete, черновики, состояния, сохранение и восстановление; интегрируй с существующей системой сессий/событий.
- **Resource adapter/resolver**: аннотация как ресурс или типизированный объект, ссылающийся на оригинальный ресурс. `r1` — пример ссылки на ресурс, `e1` — элемент, `a1` — аннотация. Это **только пример семантики**, точный синтаксис и scope взять из актуального Context Explorer; не создавать параллельное пространство идентификаторов. Alias должны разрешаться в стабильные ID.
- **Chat composer**: структурированные чипы/attachments, а не вставленный JSON; add/edit/remove, draft, send/retry, восстановление сессии, переход к цели. При compaction ссылки не должны становиться неразрешимыми.
- **Agent**: читает аннотацию через существующий resource API, затем исходники через существующие tools. Изменяет **исходный файл**, не временный DOM. Проверяет конфликт версии, результат и сообщает об ограничениях.

## Минимальная схема данных (адаптировать к действующим контрактам)

```json
{
  "schemaVersion": 1,
  "id": "ann_stable_id",
  "kind": "ui.annotation",
  "resourceRef": {"resourceId": "resource_stable_id", "revision": "optional_hash", "previewInstanceId": "preview_id"},
  "target": {
    "stableUiId": "plugins-card",
    "selector": "[data-ui-id='plugins-card']",
    "domPath": "html>body>main>div:nth-of-type(2)",
    "tag": "div",
    "textExcerpt": "Plugins",
    "rect": {"x": 320, "y": 120, "width": 240, "height": 110},
    "viewport": {"width": 1200, "height": 800, "dpr": 1},
    "sourceHint": {"file": null, "line": null, "confidence": "unknown"}
  },
  "comment": "Сделать карточку компактнее",
  "status": "draft"
}
```

Стабильный `data-ui-id` предпочтителен, но не обязателен. Селекторы, DOM-путь, текст, геометрия — **подсказки**, не гарантия идентичности. Версия ресурса нужна для stale detection. Никогда не объявлять номер строки исходника достоверным без source mapping. Снимок должен быть небольшим; полный HTML агент читает отдельно. Лимитируй размеры строк и число атрибутов. Не сохраняй пароли, значения форм, токены, cookies, приватные поля или весь `outerHTML` без фильтрации. Скриншоты в будущем — отдельные ресурсы, не base64 в сообщениях.

## Поиск исходника и внесение правок

1. Найди ресурс и проверь его revision.
2. Пробуй stable UI ID, затем уникальный id/семантические атрибуты, затем selector + текст + структуру; при доступности — source map/dev metadata.
3. Различай статический HTML и DOM, сгенерированный JS. Не правь DOM-снимок как будто это исходник.
4. Если кандидатов несколько или цель исчезла — пометь `ambiguous/stale/unresolved`, запроси уточнение. Не исправляй первый похожий узел.
5. Применяй изменения существующим механизмом безопасных мутаций/patch с проверкой версии, конфликтов и возможностью rollback.
6. Повторно открой preview, проверь наличие цели и требуемое поведение. Если автоматическая проверка невозможна, сообщи это явно.

## WebView2 и безопасность

Инъекция только в доверенные preview и разрешённые интерфейсы плагинов. Проверяй origin, previewInstanceId, message schema, размер payload и полномочия. Страница не может передать произвольный путь и получить право записи через bridge. Не смешивай trust boundary плагина и host. Содержимое DOM/комментариев считать недоверенными данными для LLM. Обработай CSP, SPA-перерисовку, scroll/zoom, shadow DOM, iframe; для cross-origin iframe явно показывай ограничение. Dispose удаляет listeners/overlay при смене страницы. Собственный чат/панель управления не должны случайно попадать в inspect mode.

## Этапы и критерии приёмки

### Фаза 0 — аудит и ADR
Результат: карта кода, совместимый контракт, список изменений и тестов. Gate: отсутствует дублирование resource store/bridge/patcher.

### Фаза 1 — JS Inspector MVP
Hover, рамка, click select, Escape, выключение, cleanup, корректное позиционирование при scroll/resize, fixture с вложенными элементами и динамическим DOM. Gate: при Off страница ведёт себя как прежде; нет утечек обработчиков и перехвата кликов.

### Фаза 2 — Annotation UI + composer
Несколько комментариев, редактирование/удаление, чипы, draft, отправка и retry. Gate: чипы разрешаются в правильные объекты, двойной клик/повторное событие не создают дублей, текст не теряется при закрытии popup.

### Фаза 3 — Resource/bridge интеграция
Подключение к HTML-библиотеке и плагинам, сохранение и восстановление ссылок, валидация событий WebView2. Gate: при повторном открытии аннотация находится либо помечается stale/unresolved; нет несанкционированных файловых операций.

### Фаза 4 — agent workflow
Skill/инструкция: разрешить `a1` → найти исходник → оценить confidence → изменить штатными tools → проверить → отчитаться. Gate: успешная правка тестового HTML/CSS и безопасный отказ при неоднозначной цели.

### Фаза 5 — расширения после MVP
Inspect-only `e1`, собственный UI RNAssistant, source maps, скриншоты, групповые выделения, reattach после перестроения DOM, визуальная регрессия. Не включать в критический путь MVP без оснований.

## Тестовая матрица

- Вложенные div/button, одинаковые классы, дублирующиеся тексты.
- Scroll, resize, zoom, CSS transforms, overflow, fixed/sticky элементы.
- Shadow DOM и iframe (включая недоступный cross-origin).
- SPA rerender, навигация, закрытие preview, повторное включение режима.
- Несколько аннотаций на один элемент, два ресурса с похожим DOM.
- Повторные bridge events, retry send, reopen chat, compaction.
- Удалённый/изменённый ресурс, несовпадение revision, неоднозначная привязка.
- Недоверенный HTML, длинные атрибуты, sensitive form fields, поддельные bridge messages.
- Отсутствие регрессий в обычных кликах, клавиатуре, чате, рендере плагинов и файловых инструментах.

## Не делать

Не создавать новый браузер, отдельную БД, универсальный DOM snapshot storage, параллельную систему ссылок, второй patch engine, прямое изменение файлов из инспектора, обязательный framework/TypeScript/bundler, скрытые автоисправления или массовую перепись UI. Не внедрять Chrome DevTools Protocol до доказанной необходимости: простой JS Inspector — стартовый вариант; CDP — возможный адаптер в будущем.

## Итоговые deliverables

1. Аудит с путями к реальным компонентам и ADR.
2. Минимальный код Inspector + annotation integration + тестовые fixtures.
3. Контракт ссылок/ресурсов и агентный skill, встроенные в существующую архитектуру.
4. Автотесты JS, доступные интеграционные тесты и отдельный Windows/WebView2 smoke checklist.
5. Документация пользователя: открыть HTML → Annotate → выбрать → написать → отправить → проверить исправление.
6. Отчёт: что сделано, какие тесты прошли, ограничения, известные риски, оставшиеся этапы.

**Приоритет:** стабильность, переиспользование, простота и отсутствие новых классов багов важнее количества функций. Агент обязан сначала проверить предложенную архитектуру, а не слепо реализовывать этот план.
