# Changelog

User-visible changes are recorded here. Internal stabilization work is tracked in
[PROGRESS.md](docs/stabilization/PROGRESS.md). A commit is not a release.
Completed product changes add an Unreleased note with their assigned development
version; dated version sections belong to explicit release preparation. See
[Versioning](docs/operations/VERSIONING.md) for bump rules and the transition from
the previous freeze. Unreleased notes do not claim published or qualified builds.

Historical baseline: `v16.0.4`. This file does not reconstruct historical release notes.

## [Unreleased]

### 17.6.18-dev

- Материалы показывают первый кадр не более чем за 50 строк и раскрывают уже
  загруженные элементы следующими пачками по 50 без повторного bridge-чтения.
  Render дерева HTML-workspace переиспользует зависимости до изменения состава,
  содержимого, ревизии или активного HTML-материала.

### 17.6.17-dev

- Audit/GC CAS и очистка runtime data выполняются на bridge worker, а `Bootstrap`
  публикуется только после успешного завершения блока очистки. Операции без
  безопасной кооперативной отмены больше не объявляют себя cancellable и получают
  увеличенное, но ограниченное ожидание UI.
- Поиск scope в SQLite-проекции проходит через существующий
  `JournalIndexAdmission`, после чего gate освобождается до inventory/repair.
  Повреждённый индекс сохраняет единственный прежний repair path без lock inversion.
- `core.search` больше не обещает продолжение после смены run или handler: старый
  результат явно помечается `nextExpired` и требует нового поиска, а живой
  continuation сохраняется только у последнего поиска текущего run. Уточнены
  диагностика admission/CAS и ошибки точного поиска; прямой ToolRuntime использует
  ту же узкую нормализацию singleton-массивов, что и v8 parser.

### 17.5.0-dev

- Office text search и replacement используют единый model-facing словарь:
  `query`/`limit` для поиска и `query`/`replacement` для Excel, Word и PowerPoint.
  Старые `maxResults`, `find` и `replace` не принимаются как скрытые aliases; меняются
  exact contract revisions, поэтому сохранённые frozen admissions требуют fresh
  re-admission. `maxItems` Outlook, `maxReplacements` и preview-поля сохранены.
- `core.replace` теперь может выполнить подтверждаемую inline-замену одного точного
  target без отдельного `core.search`: runtime сам читает полный source, строит
  exact plan и разрешает 1–100 совпадений. При явном `expectedMatches` остаётся
  строгий путь через завершённый поиск и его точный count. Оба режима сохраняют
  confirmation, source guard, owner read-back и правило не повторять Unknown.

### 17.4.4-dev

- Исправлена совместимость journal replay с .NET Framework 4.8: outcomes больше
  не копируются через отсутствующий в net48 конструктор `Dictionary`.
- Metadata и queue-input commits сохраняют canonical run checkpoint вместо
  устаревшего `LastRun` из UI-снимка, поэтому edit/cancel и peer input не
  конфликтуют с уже записанным состоянием run.
- Aggregate package operation после подтверждённого изменения больше не требует
  model origin для продолжения; неизвестный результат по-прежнему закрыт от
  автоматического повтора.

### 17.4.3-dev

- Исправлен запуск после создания или пересборки общего индекса: fingerprint
  принятого `chat.committed` теперь проверяется по исходному payload, а не после
  JSON round-trip через текущие типы. Добавленные позже default-поля больше не
  превращают сохранённый chat frame в `Invalid chat commit` и не блокируют панель.

### 17.4.2-dev

- Model-facing `core.search` теперь принимает `detail=context` для двух ограниченных
  соседних строк и `next=true` для продолжения последнего незавершённого поиска без
  передачи модели внутренних cursor-координат. Точные позиции, ревизии и source pins
  остаются runtime-owned; изменение аргументов, состава источников или ревизии
  завершает продолжение явной ошибкой.
- Workspace-поиск сам проходит до четырёх пустых страниц, поэтому разреженное
  совпадение больше не требует дополнительных model turns. Проекция результата
  использует один консервативный `complete`; для неполного поиска количество
  наблюдённых совпадений называется `matchesSeen`, а не выдаётся за точный итог.
  `core.replace` по-прежнему требует завершённого точного поиска одной цели.

### 17.4.0-dev

- Markdown-документы теперь используют один ограниченный разбор Markdig для
  отформатированного просмотра, дерева заголовков, точных диапазонов разделов и списка
  ссылок. Просмотр сохранённых материалов получил режимы MD и исходника, а Workspace и
  документные ресурсы используют общий outline и выбор
  уникального ATX/Setext-раздела без права записи.
- Материалы и Browser используют единый shell с левой навигацией, одной верхней
  панелью, раскрываемым поиском, общими действиями версий/скачивания/меню и нижним
  status bar. Форматные режимы, PDF thumbnails, коллекции и Browser address остаются
  слотами конкретного представления; MD получил ограниченный граф заголовков и явных
  ссылок. Список HTML и остальных файлов Browser перенесён в левый sidebar с деревом
  папок и выделением активного файла. Browser больше не дублирует адрес отдельным
  title/meta: версии, сохранение
  и применение объединены в одно меню, а project/export/compare/screenshot действия
  перенесены в единственный `…`. Деревья и viewer-контейнеры используют более плотные
  общие отступы без потери hit areas. Страницы PDF и полотно изображений занимают всю
  оставшуюся область после переноса миниатюр в sidebar, а повтор чтения показывается
  только при ошибке успешного exact-материала. Ширина левой панели материалов и Browser
  меняется общим splitter и сохраняется; коллекции выводятся в ней компактным
  вертикальным списком. PDF-страница больше не имеет лишней скруглённой рамки, MD-редактор
  начинается без внешних отступов и использует общий фон surface, а retry анализа MD
  показывается рядом с причиной в status bar.
- Добавлена работа с Power Query в привязанной книге Excel: поиск запросов,
  чтение M через `core.read`, точечная правка/замена через `core.patch/write`
  с проверкой исходной версии и отдельное создание определения запроса.
- Адресное обновление существующей загрузки и создание загрузки на новый либо
  полностью пустой лист используют точную связь запроса с таблицей. Тайм-аут
  ожидания не объявляется отменой или успехом; операция продолжает наблюдаться
  владельцем сессии, а неопределённый результат не повторяется автоматически.
- Добавлены отдельный статус операции и ограниченные проверки загруженных
  данных: столбцы, число строк, пустые/повторяющиеся ключи и ошибки ячеек.
  Успешная запись M не означает успешное исполнение; неполная проверка данных
  явно возвращает `not_checked`.
- Исправлена доставка прочитанного M в контекст агента: source read явно сообщает
  о включённом тексте, сохраняя границы полного/частичного чтения. Последующая
  правка использует это подтверждение без ослабления проверки исходной версии.
- `excel.query.validate(kind=source)` проверяет синтаксис M официальным offline
  parser Microsoft 5.0.0 в отдельном локальном WebView2 worker. Результат содержит
  первую синтаксическую/лексическую ошибку с позицией либо `passed/not_checked`,
  привязан к сохранённому исходнику и показывает, совпадает ли с ним текущий M.
  Проверка не вычисляет запрос; Node/Python пользователю не требуются.
- Лимит анализа — 262144 UTF-16 символа. Недоступный host, тайм-аут, отмена,
  превышение лимита или внутренний сбой не выдаются за корректный M либо его ошибку.
  Разрешение имён, зависимости и доступ к источникам остаются отдельными проверками.
- Подтверждённая остановка refresh с неизвестным итогом больше не блокирует новый
  явно запрошенный вызов навсегда: требуется свежее чтение статуса именно той
  операции. Исторический Unknown сохраняется; закрытие книги само по себе такой
  повтор не разрешает. Новая worksheet load проверяет фактическую связь с Data Model
  перед refresh и явно отказывает при неподдержанном соединении.
- Используются общий просмотр ресурсов/различий и встроенная инструкция Excel.
  Работа с Data Model, вычисляемый preview, native cancel и безопасное
  переименование/удаление запросов остаются за рамками среза. Реальная
  Windows/Office/WebView2 qualification ещё открыта.

### 17.3.20-dev

- Повторная публикация одного и того же exact resource view больше не блокирует

  адресованные heads при сохранении общей generation. Большое число несвязанных

### 17.3.15-dev

### 17.3.14-dev
