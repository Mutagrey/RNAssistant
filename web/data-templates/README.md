# Data Templates

Самостоятельное приложение для преобразования табличных данных. Эта папка —
исходный workspace-проект приложения. RNAssistant может редактировать, проверять
и использовать его, но не нужен для запуска браузерной версии.

## Запуск

Откройте `index.html` в браузере: доступны выбор файлов и папок, drag-and-drop,
поиск, фильтры, страницы списка, прогресс и отмена подбора. Затем на вкладке
«Шаблоны» выберите или перетащите JSON-шаблон. Отдельный Worker до запуска
проверит язык, правила и справочники; ошибки блокируют запуск. Здесь видны
лист и области, а на вкладках «Параметры» и «Маппинг» — списки с поиском.
Значения источника проверяются при обработке каждого файла. После проверки
запустите очередь. Сейчас выполняется только выборочное чтение XLSX.
Файлы обрабатываются последовательно
в Worker; ход работы, ошибки и отмена видны на вкладке «Результаты».

Для первого запуска скачайте `core/examples/matrix-xlsx-extraction.json` и
`core/examples/matrix-source.xlsx`. Результат содержит 16 наблюдений с
происхождением. Интерфейс показывает первые 20 записей; для каждого успешного
файла можно скачать полный JSON результата. При доступном файловом хранилище
браузера он записывается порциями: до 256 МиБ записей на файл и 1 ГиБ за запуск.
Если это хранилище недоступно, явный резервный режим хранит до 8 МиБ на файл в
памяти. Это временный экспорт извлечения, а не опубликованный dataset.
Отдельный `core/index.html` остаётся проверочным инструментом ядра с
диагностическим отчётом.

При открытии через `file://` нормализованные JSON-примеры в отдельной проверке
работают в явно выбранном базовом режиме. XLSX в основном приложении и проверке
требует Worker и статической HTTP(S)-раздачи этой папки: браузер может запретить
Worker при двойном клике. Приложению не нужен серверный код, аккаунт, Office,
.NET или RNAssistant. Автоматического перехода с Worker на главный поток нет.
Входной XLSX ограничен 96 МиБ; обработка настоящих книг на 80 МБ пока не
квалифицирована. CSV/JSON можно подобрать, но их чтение в этой очереди пока
недоступно и явно отмечается ошибкой.

## Границы

- `application.json` описывает поставку приложения: UI, ядро, примеры, проверки
  и лицензии. Это не `project.json` пользовательского проекта данных.
- `ui/` — общие разметка, представления и владелец подбора; `ui/browser.js` —
  браузерная композиция. `processing.js` владеет очередью, отдельные модули
  проверки шаблона — предварительной проверкой и просмотром, `result-staging.js` —
  порционной записью во временное хранилище браузера и ограниченным резервным
  режимом в памяти, а представления — только DOM.
  Состояние и File handles живут вне представлений.
- `styles/` — дизайн-токены, компоненты и браузерная тема; UI не зависит от темы.
- `core/` — единственное JS-ядро, Worker и проверочный интерфейс. Правила шаблонов
  не дублируются в C#.
- `vendor/` — локальные версии библиотек и их лицензии; `vendor-lock.json` фиксирует
  происхождение, размеры и SHA-256 каждого файла.
- `tests/` — переносимые проверки ядра; `tools/` — инструменты разработки.

Исходники, шаблоны, словари и результаты пользователя относятся к отдельным
проектам данных. Они не добавляются автоматически в экспорт приложения.
RNAssistant хранит свой адаптер снаружи этой папки: workspace-файлы, права,
подготовка снимков, Office и нативный канал выполнения не являются зависимостями
браузерной поставки. Загрузка manifest не даёт разрешения исполнять проектный JS
в привилегированном окне RNAssistant.

## Разработка и экспорт

Исходники — обычные HTML/CSS/JS, без npm и сборщика. Для следующих команд нужен
только Node как инструмент разработки; пользователю приложения он не нужен:

```sh
node tests/core.test.js
node tests/matrix.test.js
node tests/universal.test.js
node tools/export.js /absolute/path/to/new-folder
```

Для экранов результатов предусмотрен ECharts 5.6.0, для таблиц маппинга и данных —
Tabulator 6.5.0. Браузерный адаптер загружает их только при вызове
`DataTemplatesVendors.load("echarts")` или `load("tabulator")`; при открытии
приложения они не исполняются. Передавать им следует агрегаты или ограниченные
страницы, а не всю книгу. При закрытии вида нужно вызывать `chart.dispose()` или
`table.destroy()`.

SheetJS CE 0.20.3 включён для будущего чтения XLSB/старых Excel-форматов и записи
Excel. Он не запускается в основном окне и пока не подключён к рабочему импорту.
Будущий адаптер должен выполнять его в отдельном Worker с ограничениями памяти,
входа и отменой. SheetJS читает файл целиком: наличие библиотеки не означает,
что XLSB или книги 80 МБ уже поддержаны. Текущий XLSX-путь остаётся выборочным.
Окончательный выбор между SheetJS для всех Excel-форматов и выборочным/смешанным
чтением открыт. До завершения рабочего импорта нужно сравнить реальные большие
XLSX/XLSB по памяти, времени, отмене, точности и происхождению значений; решение
зафиксировать вместе с правилом выбора читателя.
Версии меняют через отдельную проверку лицензий, хэшей и сценариев браузера.

Экспорт берёт только явные `application.json.files`, отклоняет выходящие за пределы проекта пути
и символические ссылки и не перезаписывает существующую папку. Все файлы, включая
проверки и экспортёр, остаются редактируемыми. `application.lock.json` фиксирует
размеры и SHA-256 экспортированных файлов; это опись пакета, не разрешение native
host и не доказательство успешного преобразования. При добавлении файлов обновите
manifest. Экспорт проверяет также точные файлы из `vendor-lock.json` и их лицензии.
После изменений повторите проверки и экспортируйте в новую папку.

При новом запуске приложение удаляет прежние результаты, а при обычном закрытии
вкладки запрашивает удаление. После сбоя или прерванного закрытия временные файлы
могут остаться в хранилище браузера; при следующем создании результата приложение пытается
удалить файлы старше 24 часов. Скачайте нужные результаты до закрытия вкладки.

Редакторы шаблонов/маппинга (текущий просмотр только для чтения), проектное сохранение результатов, сохранение
проектов данных, исходные CSV/JSON и другие Excel-форматы (включая XLSB),
публикация dataset и сборка в один HTML остаются следующими этапами. Сначала завершается
самостоятельный пользовательский сценарий, затем тот же сценарий подключается
к RNAssistant через адаптер.
